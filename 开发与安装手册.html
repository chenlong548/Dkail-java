第一部分：项目概述

1.1 项目定位

DKail 是一款面向安全学习场景的轻量级主机安全监控系统。项目采用 Java (Spring Boot) 后端 + React (Tauri) 前端架构，提供实时网络流量监控、进程监控、系统资源监控及威胁检测功能，最终打包为原生桌面应用。

本项目全程采用 AI Agent 协同开发模式，本文档将完整呈现人机协作的开发过程，供学习者参考。

后端核心服务开发
开发者 → Agent

目标

开发者 Prompt

[开发者] 伪代码已审核通过，现在实现后端所有 Java 代码。项目目录：Dkail-java/ 要求： - Maven 项目，Spring Boot 3.2.0，Java 17，Lombok - 依赖：spring-boot-starter-web、pcap4j-core、pcap4j-packetfactory-static、jna - 编码 UTF-8，避免 Windows GBK 乱码 - 13 个 Model 类放在 com.dkail.model 包下 - 4 个 Service 类放在 com.dkail.service 包下，实现 Runnable 接口 - 1 个 ApiController 放在 com.dkail.controller 包下，6 个 GET 端点 - DkailApplication 主入口通过 CommandLineRunner 启动 4 个监控线程 - SystemState 使用 synchronized 集合保证线程安全 - NetworkMonitor 需要处理 Pcap4J 不可用时的降级逻辑 - ProcessMonitor 使用两次采样差值法计算 CPU%，需除以 CPU 核心数 - SystemResourceMonitor 通过 WMI 两次采样计算网络速率（bytes/s） - ThreatDetector 需要告警去重机制 请生成完整的 Maven 项目结构和所有 Java 源文件。

关键实现细节

3.1 NetworkMonitor — 网络监控

  • 主模式：Pcap4J 抓包，实时解析 TCP/UDP 数据包
  • 降级模式：无 Npcap 时自动切换为 netstat -an 解析
  • 通过 SystemState 共享连接列表和数据包统计
// 自动检测 Npcap 可用性 try { PcapHandle handle = Pcap.openLive(deviceName, snapLen, mode, timeout); // Pcap4J 模式 } catch (Exception e) { log.warn("Pcap4J unavailable, falling back to netstat mode"); // netstat 降级模式 }

3.2 ProcessMonitor — 进程监控

  • 通过 PowerShell Get-Process 获取进程列表
  • CPU 使用率：两次采样差值法，除以 CPU 核心数
  • 按 CPU 降序排列，取 Top 100 进程
CPU% = (Δ累计CPU时间 / Δ采样间隔) / CPU核心数 × 100

3.3 SystemResourceMonitor — 资源监控

  • CPU/内存：反射调用 com.sun.management.OperatingSystemMXBean
  • 磁盘：File.getTotalSpace() / File.getFreeSpace()
  • 网络速率：WMI Win32_PerfRawData_Tcpip_NetworkInterface 两次采样差值
Rate(B/s) = (Δ累计字节数 / Δ采样间隔)

3.4 ThreatDetector — 威胁检测

  • 规则引擎：可疑进程名匹配（mimikatz、nc、cobaltstrike 等）
  • 阈值检测：CPU > 80%、内存 > 500MB 触发告警
  • 告警去重：alertedProcesses 集合防止重复

3.5 DkailApplication — 主入口

@Bean public CommandLineRunner startMonitors(SystemState state) { return args -> { ScheduledExecutorService pool = Executors.newScheduledThreadPool(4); pool.submit(new NetworkMonitor(state)); pool.submit(new ProcessMonitor(state)); pool.submit(new SystemResourceMonitor(state)); pool.submit(new ThreatDetector(state)); }; }

3.2 关键算法

进程 CPU 使用率（ProcessMonitor.java）

PowerShell Get-Process 返回的 CPU 字段是累计 CPU 时间（秒），不是使用率百分比。通过两次采样差值法计算：

CPU% = (本次累计CPU时间 - 上次累计CPU时间) / (本次时间 - 上次时间) / CPU核心数 × 100

除以核心数后，各进程 CPU% 加和约等于任务管理器中的总 CPU 使用率。

网络速率（SystemResourceMonitor.java）

WMI Win32_PerfRawData_Tcpip_NetworkInterface 的 BytesReceivedPersec/BytesSentPersec 是累计原始计数器值，两次采样差值除以时间得到实时速率：

Rate(B/s) = (本次累计字节数 - 上次累计字节数) / (本次时间 - 上次时间)

GET /status

系统运行状态。

{ "network_monitor_active": true, "process_monitor_active": true, "threat_detection_active": true, "alert_count": 3, "uptime": 3600 }

GET /resources

系统资源使用率。network_in/network_out 为实时速率（bytes/s）。

{ "cpu_usage": 23.5, "memory_usage": 78.0, "disk_usage": 80.1, "network_in": 505202, "network_out": 25376 }

GET /processes

进程列表，按 CPU 降序，最多 100 条。

{ "processes": [ {"pid": 1234, "name": "java.exe", "path": "", "cpu_usage": 3.5, "memory_usage": 256.8} ], "count": 100 }

GET /network

网络连接与统计。

{ "connections": [ {"local_addr": "192.168.1.5:5173", "remote_addr": "127.0.0.1:8080", "protocol": "TCP", "state": "ESTABLISHED"} ], "packet_count": 27752, "byte_count": 23200000 }

GET /alerts

告警列表。

{ "alerts": [ {"id": 1, "timestamp": "2026-06-12T19:30:00", "alert_type": "SuspiciousActivity", "severity": "High", "source": "system", "description": "Detected suspicious process: nc.exe", "details": {}} ], "count": 1 }

GET /health

{"status": "ok", "timestamp": 1718192400000}

4.4 常见问题

Q: 启动后端报 Pcap4J 相关错误？

A: 系统会自动检测 Npcap 是否安装。未安装时自动降级为 netstat 模式，不影响基本功能。如需完整抓包能力，请安装 Npcap。

Q: 进程 CPU 使用率首次显示为 0？

A: 首次采样无法计算差值，第二次采样（约 3 秒后）开始显示真实 CPU 使用率。

Q: 网络速率首次显示为 0？

A: 同上，首次采样无差值可计算，约 1 秒后开始显示实时速率。

Q: Tauri 构建报 cargo not found？

A: 需将 Rust 的 cargo 路径加入系统 PATH：

$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"

Q: Tauri 构建报图标缺失？

A: 运行 npx tauri icon <图标路径> 生成完整的图标文件集。

Q: 前端页面空白或无法连接后端？

A: 确认后端已启动（访问 http://127.0.0.1:8080/health 返回 OK），开发模式下 Vite 代理会自动转发 API 请求。
